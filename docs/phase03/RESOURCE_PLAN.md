# 第三階段資源估計

純數學驗證及 PNG 校準已啟動後，我在正式 JPEG 批次開始前，依同機前一階段紀錄和第三階段 HDF5 讀寫測試估計批次資源。

| 項目 | 根據與估計 |
|---|---|
| 主機 | 13th Gen Intel Core i3-1315U，6 個實體核心、8 個邏輯處理器，約 34 GB 記憶體 |
| 任務大小 | 32 組 × 100 個 JPEG 品質條件 × 38,088 個區塊，共 121,881,600 個受攻擊區塊 |
| 儲存 | 從 float64 矩陣、因子、轉移與判決欄位估算壓縮前約 125 GB。執行前確認磁碟剩餘空間約 1.7 TB，預留 200 GB |
| Python JPEG | 同機第二階段 800 個條件的執行日誌首末寫入相隔 286 秒。第三階段條件數四倍，另寫完整左右 SVD 因子，以約 25～45 分鐘作排程估計 |
| MATLAB 逐塊分析 | 資料交換測試處理 100 組 38,088 區塊的 HDF5 輸入、排序統計及分批輸出，測試期間與 P 校準共用 CPU。正式以兩個 MATLAB 工作程序與 Python 影像流程並行，預留 35～90 分鐘 |
| 工作分配 | PNG 校準按方法分派程序。正式 JPEG 以五個程序逐方法處理。每個 JPEG 條件寫入後保存完成標記。MATLAB 分析以十個 QF 為一個檢查點，作圖依圖號分兩批 |

執行時的 CPU 競爭、HDF5 壓縮率及系統負載會影響時長。研究報告使用實際校準及提取時計，不以排程估計代替量測。

正式批次開始後，我依首批兩個 MATLAB 方法的實測資源調整方法級排程。JPEG 運行中最多三個 MATLAB 工作程序，全部 JPEG 完成後最多六個。已完成的方法與 QF 檢查點可直接續用。
